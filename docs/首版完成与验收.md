- 本项目 AGENTS.md 明确所有 Agent 必须在完成修改和验证后提交本地 Git，多 Agent 由主 Agent 统一提交，推送须有用户授权。

本次验证：63 项测试全部通过，包含真实 Microsoft Word 来源分页、分册重新分页、PDF 内部跳转及从拆标到待签章输出的合成闭环。源码包和 wheel 构建成功。实际查看合成闭环两个分册共4页，未发现裁切、重叠、缺字或表格越界。沙箱内 Word 自动化曾卡住，清理测试专用进程后，在正常 Windows 权限下完成全部验证。

本次验证针对软件功能和合成场景。真实项目仅用于拆标试点，尚未完成全流程实标验收；产品继续标记“待实标验收”。以下为首版原始验收记录，其中当时的远程仓库和资料收集状态不代表当前状态。

## 验收结论

BidFlow 0.1.0 已完成计划内的软件开发和合成场景验收。程序可在独立项目文件夹内完成资料导入、全量拆标任务、规则与证据映射、确定性计分、人员组合、技术策划、正文任务、独立复核、表单填充、分册组卷、实际分页、资格及评分索引、PDF跳转核验和待签章输出。

当前产品状态保留为“待实标验收”。这是首版范围中的明确状态：尚未收到真实咨询服务项目材料，因此没有把合成测试结论写成真实投标质量结论。

## 最终验证结果

- 自动化测试：`59 passed`。测试包含真实 Microsoft Word 来源分页、分册分页、目录字段、PAGEREF、PDF书签和完整端到端闭环。
- OCR：RapidOCR 3.9.2 与本地 ONNX Runtime 使用随包本地模型，实际识别“项目负责人须具有高级职称”，置信度 0.99991；程序运行时未触发模型下载。
- Word/PDF：最新合成闭环输出商务、技术两个分册，各2页；结构校验无错误，商务册8个内部跳转、6个页码引用，技术册9个内部跳转、8个页码引用。
- 视觉检查：逐页检查最新4页渲染图，无裁切、重叠、缺字、表格越界和页眉页脚错位；已去除内置标题蓝色装饰线及重复章节标题。
- 打包：源码包和wheel构建成功；wheel在全新的Python 3.12.10环境安装成功，命令入口、项目初始化、内置项目规则和Word脚本均可用，依赖检查无冲突。

本机缺少LibreOffice，因此文档技能附带的LibreOffice渲染器按预期报告缺少`soffice.exe`。本项目依赖 Microsoft Word 的真实分页和PDF导出，最终视觉检查使用Word实际导出的PDF及工作区内置Poppler逐页渲染完成。该限制不影响本机首版运行；换机后应先运行`bidflow doctor`。

## 保留边界

- 外部钉钉、飞书和合同系统自动连接未纳入首版；当前提供人工检索任务和本地回填入口。
- 暗标未纳入首版；识别后直接阻止自动组卷。
- 签字盖章、授权有效性、保证金、上传和递交必须人工完成。
- 商务分为证据支持的投标阶段测算，技术分为独立Reviewer模拟分，报价分单列；均不表示评委最终得分。
- 至少使用一套真实咨询服务项目完成规则金标准、证明页、正文和成品人工核对后，才可把产品状态从“待实标验收”改为“实标验收通过”。
