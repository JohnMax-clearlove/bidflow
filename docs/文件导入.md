# 文件导入、解析与检索

本说明面向实际整理资料的人员。导入的原则是：原始文件保留、派生文本可重建、每条分析结论能够回到文件、页码或结构位置。

## 资料放在哪里

每个投标项目的 `01_输入文件` 有八个分类目录：

| 目录 | 主要内容 |
|---|---|
| `01_招标文件` | 招标文件及澄清补遗 |
| `02_公司证照` | 营业执照等主体材料 |
| `03_公司资质` | 资质证书及许可 |
| `04_荣誉奖项` | 奖项和荣誉证明 |
| `05_人员证书` | 职称、职业资格等证书 |
| `06_企业业绩证明` | 合同、成果验收等企业业绩材料 |
| `07_人员业绩证明` | 能够明确人员角色的证明材料 |
| `08_其他补充资料` | 招标表单、承诺模板及其他材料 |

公司公共资料库另有 `09_方法论`、`10_历史章节` 和 `11_业绩台账`。这些内容用于检索和候选筛选，不能直接充当本项目的正式证明。

澄清补遗与招标文件放在同一目录。单独导入补遗时必须指定类别：

```powershell
bidflow ingest ".\01_输入文件\01_招标文件\补遗一.pdf" --category 澄清补遗 --project .
```

## 批量导入

把文件放好后运行：

```powershell
bidflow ingest --scan --project .
```

扫描会按一级分类目录判断资料类别，跳过 Word 临时文件。支持：

- 文档：DOCX、PDF、Markdown、TXT；
- 图片：PNG、JPG、JPEG、BMP、TIF、TIFF、WEBP；
- 台账：XLSX、XLSM、CSV、TSV。

旧版 `.doc` 和 `.xls` 需要先另存为 DOCX 或 XLSX。扫描目录中的表格文件按业绩台账导入；单独导入台账也可运行：

```powershell
bidflow ledger ".\01_输入文件\08_其他补充资料\业绩台账.xlsx" --project .
```

从项目外导入文件时，BidFlow 会复制到对应分类目录并核对哈希。同名但内容不同的文件会加哈希后缀，已有原件不会被覆盖。同一内容再次导入会复用解析缓存。

## 解析结果怎么看

每个文件会登记为 `DOC+哈希前12位`，每个分块会登记为 `DOC…-B00001`。文件记录在 `.bidflow/records/files.json`，分块记录在 `.bidflow/records/blocks.json`；人通常不需要手工修改它们。

解析缓存位于 `.bidflow/cache/parse`，其中可能包含：

- `clean.md`：带分块编号的清洗文本；
- `structure.json`：段落、表格、页码、坐标、识别质量和警告；
- `pandoc.md`：Pandoc 可用时生成的语义参考稿；
- 页面预览或 Word 渲染副本。

PDF 使用物理页码。DOCX 在 Windows 桌面版 Word 可用时，会在副本中加入定位书签并渲染，以“Word 渲染页码”记录来源；不会修改原 DOCX。无法完成渲染时仍保留段落和表格位置，页码保持未知，Agent 不得猜页码。

复杂表格、修订、文本框、嵌入对象、页眉页脚、扫描页及低质量识别会标记为 `review`。空白提取或解析失败表示“尚未可靠读取”，不能据此认定原文没有要求。

## 扫描件和 OCR

先检查环境：

```powershell
bidflow doctor --project .
```

对单个扫描文件启用本地 OCR：

```powershell
bidflow ingest ".\01_输入文件\01_招标文件\扫描招标文件.pdf" --category 招标文件 --ocr --project .
```

OCR 依赖 RapidOCR、ONNX Runtime 和本地 `det`、`cls`、`rec` 模型。程序不会联网下载模型。缺少依赖或模型时，原页预览仍会保留，并生成待人工核对警告。

识别质量为 `review` 的规则来源或证明页，需要在 Agent 结果中记录对原页的视觉核验；仅有 OCR 文字不能自动升级为可靠证明。

## 业绩台账

程序能自动识别常见中文列名，例如：项目名称、合同编号、合同签订日期、委托单位、项目类型、服务内容、项目投资额、人员ID、人员姓名和人员角色。

台账应尽量提供稳定的人员ID。没有人员ID时，同名人员不会自动合并，而是按来源行建立候选身份。只有“项目成员”记载时，程序不会推断为项目负责人或主持人。公式单元格不会被当作事实值。

列名不同可提供映射文件：

```json
{
  "project_name": "项目全称",
  "contract_no": "协议编号",
  "staff_id": "员工编号",
  "staff_name": "姓名",
  "role": "承担岗位"
}
```

```powershell
bidflow ledger ".\台账.xlsx" --mapping ".\台账列映射.json" --project .
```

导入报告写入 `03_资料匹配/台账导入报告_DOC编号.json`。台账记录只用于寻找候选，仍需合同、成果、任命或其他正式材料证明项目事实和人员角色。

## 中文检索和公司资料库

检索当前项目：

```powershell
bidflow search "项目负责人" --project .
bidflow search "咨询服务" --category 企业业绩证明 --limit 30 --project .
```

同时查公司资料库：

```powershell
bidflow search "商业策划" --library --project .
bidflow connector local_library "三级复核" --project .
```

中文长词优先使用 SQLite FTS5 trigram；两字姓名、短词或数据库不支持 trigram 时会采用受控子串检索。返回的是资料线索，不是“符合招标要求”的结论。

选中公司资料库中的材料后，要把原件导入当前项目并重新核验。相对路径在当前项目不存在时，导入命令也会到已配置的公司资料库中寻找：

```powershell
bidflow ingest "01_输入文件/08_其他补充资料/合成方法论.md" --category 方法论 --project .
```

索引丢失或需要重建时运行：

```powershell
bidflow reindex --project .
```

钉钉、飞书和合同系统当前没有自动接通。以下命令只会返回人工检索任务，不会访问外部账户：

```powershell
bidflow connector dingtalk "合同编号 HT-2026-001" --project .
```

人工下载后将原件放入项目分类目录，再运行 `ingest --scan`。
