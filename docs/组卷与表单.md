# 商务表单、组卷与输出

BidFlow 先维护 Markdown 正文和可编辑商务表单，再生成审阅组卷。只有实际分页、结构核验、人工视觉检查和版本确认均完成后，才能封存为“待签章”文件。

## 共用字段

项目名称、投标人名称、截止时间、服务期和报价等共用值保存在 `facts`。查看当前值：

```powershell
bidflow data show facts --project .
```

由用户核对后准备 JSON，例如：

```json
{
  "company_name": "北辰合成咨询有限公司（虚构）",
  "deadline": "2026-12-31",
  "service_period": "90日",
  "price": "980000.00",
  "price_upper": "玖拾捌万元整"
}
```

```powershell
bidflow data import facts .\项目共用字段.json --actor 项目负责人 --project .
```

报价必须由用户确定。程序会核对人民币大小写金额，但不会替用户选择报价。

## 商务表单

表单模板必须是项目内已有的 DOCX 或 Markdown。模板可使用 `{{字段名}}` 占位符，例如：

```text
项目名称：{{project_name}}
投标人：{{company_name}}
投标报价：{{price}} 元（大写：{{price_upper}}）
服务期限：{{service_period}}
```

Agent 应先对照招标原表核查模板、字段和格式，再将表单记录导入 `forms`。表单记录至少应包含唯一编号、标题、项目内模板路径、必填字段、模板核准状态、模板哈希和招标来源定位。示例：

```json
[
  {
    "id": "FORM001",
    "title": "投标函",
    "template_path": "01_输入文件/08_其他补充资料/投标函.docx",
    "required_fields": ["project_name", "company_name", "price", "price_upper", "service_period"],
    "fields": {},
    "volume": "商务部分",
    "status": "draft",
    "template_approved": true,
    "template_sha256": "由Agent按当前模板文件计算的SHA256",
    "source_refs": [{"file_id": "DOC文件编号", "block_id": "DOC分块编号"}]
  }
]
```

```powershell
bidflow data import forms .\表单记录.json --actor 表单核验人 --project .
bidflow form FORM001 --project .
```

填充结果保存到 `05_投标文件编制/商务表单`，原模板不改动。程序会检查缺失字段、共用字段冲突、模板版本和报价大小写，并生成同名 `.检查.md`。填充成功只表示替换完成；用户核对内容和版式后，才能把表单状态更新为 `confirmed`。

## 正文和独立审核

正文以 `05_投标文件编制` 中的 Markdown 为主稿。新正式文本需要先完成项目规则要求的沟通记录和策划确认：

```powershell
bidflow confirm brief --actor 项目负责人 --project .
bidflow confirm plan --actor 项目负责人 --project .
```

逐章准备写作任务，章节编号来自策划记录：

```powershell
bidflow task prepare write --target SEC001 --project .
```

写作结果接收后生成 Markdown。用户修改并确认全文时运行：

```powershell
bidflow confirm draft --actor 项目负责人 --project .
```

独立 Reviewer 必须使用不同于 Writer 的执行者标识：

```powershell
bidflow task prepare review --target SEC001 --project .
bidflow task accept --task TASK编号 --result .bidflow/tasks/TASK编号/result.json --actor 独立审核Agent --project .
```

Reviewer 只接收评分要求、相关事实和当前正文，不接收 Writer 自评。每章最多审核 `settings.max_review_rounds` 次，默认两次；仍未解决的问题保留给人工决定。

## 生成审阅组卷

先重建报告并检查阻断项：

```powershell
bidflow reports --project .
bidflow audit --project .
```

生成单册审阅稿：

```powershell
bidflow build --mode review --project .
```

按商务、技术或自定义册号分册：

```powershell
bidflow build --mode review --split --project .
```

正文和表单保持可编辑；PDF 或图片证明材料按原页插入。资格、商务和技术索引从规则—响应关系生成，同册使用内部跳转，跨册显示“册名＋实际页码”。若招标要求禁止增加索引，将 `settings.allow_indices` 设为 `false`；Word 中不加入响应索引，内部审核索引仍保留。

`--no-render` 只生成未分页 DOCX：

```powershell
bidflow build --mode review --no-render --project .
```

未分页结果不能作为最终验收。正式分页要求 Windows 桌面版 Microsoft Word 和 PowerShell；程序在独立 Word 进程中更新目录、页码字段、书签及跨册位置并导出 PDF，不会关闭用户已经打开的 Word。

## 核验和视觉确认

```powershell
bidflow verify --project .
```

结构核验包括：

- Word/PDF 文件哈希和 PDF 页数；
- 章节与证据书签的实际目的页；
- 目录及索引 `PAGEREF` 页码；
- PDF 内部跳转；
- 分册位置文字；
- 是否含开发机绝对路径或不支持的跨文件链接。

结构通过后仍需打开 Word 和 PDF，逐页查看封面、目录、表格、横向附件、分页、图片清晰度、页码和跳转。实际检查完成后记录两项确认：

```powershell
bidflow confirm assembly --actor 项目负责人 --notes "审阅组卷内容及范围已核对" --project .
bidflow confirm visual --actor 视觉核验人 --notes "已逐页检查Word和PDF" --project .
```

任何输入、正文或输出文件改变后，旧确认与旧核验都不能沿用，应重新组卷和检查。

## 生成待签章文件

```powershell
bidflow build --mode ready --project .
```

此命令会再次检查规则、资格和必响应项、证据、正文独立审核、表单、事实一致性、组卷哈希、实际页码和确认版本。通过后，把已核验审阅稿的原字节复制到 `07_最终输出/运行编号`，状态为 `ready_for_signature`。

“待签章”仍不等于“可自动提交”。签章、授权有效性、保证金、投标平台上传、递交时间和最终人工复核由项目人员办理。完成相应事项后，可用 `data import manual_checks` 更新人工检查记录；每条记录要保留确认人和说明。

暗标在任务准备和组卷阶段都会被阻止。首版只支持咨询服务明标的单册及分册，暗标排版需另行人工处理。
