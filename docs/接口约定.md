# 开发接口约定

本文件描述程序数据格式，不承载 Agent 规则。所有主记录位于 `.bidflow/records`。

## 项目读写接口

`from bidflow.project import Project`。构造 `Project(path)` 打开已初始化项目。
- `project.root: Path`、`project.cache_dir: Path`、`project.data_dir: Path`。
- `project.meta: dict` 包含 `id,name,version,company_library,acceptance_status`。
- `project.load(name, default=None)` 读取集合；默认返回空列表。**每次调用都从磁盘重读并返回新对象**，因此
  `for row in project.load("issues"): row["status"] = "resolved"` 之后再 `project.save("issues", project.load("issues"))`
  会丢掉修改。改集合必须先取到变量：
  ```python
  issues = project.load("issues")
  for row in issues:
      row["status"] = "resolved"
  project.save("issues", issues, reason="处理冲突")
  ```
- `project.save(name, value, reason='')` 保存集合，记录修订。不得绕过此接口改主记录。
- `project.commit({name: value, ...}, reason='')` 同次提交多个集合。
- `project.safe_path(relative)` 限定相对路径在当前项目内。
- `project.fingerprint(names)` 对指定集合求哈希。
- `project.refresh_status()` 重建项目状态和各阶段可读报告。
- `from bidflow.utils import sha256_file, atomic_json, read_json, utc_now, json_hash, write_text`。

## 主记录集合（列表）

所有记录允许各模块增加所需字段，但以下通用字段含义固定。根模块最终校验这些集合。

- `files`: `id`（DOC加哈希前12位）, `path`（项目内相对路径）, `sha256`, `category`（招标文件/澄清补遗/公司证照/公司资质/荣誉奖项/人员证书/企业业绩证明/人员业绩证明/其他补充资料/方法论/历史章节/业绩台账）, `original_name`, `source`（原路径或远程来源文字）, `parser_version`, `parse_status`, `warnings`列表。
- `blocks`: `id`, `file_id`, `text`, `kind`（paragraph/table/heading/ocr）, `page`（1基，未知为null）, `section`, `locator`, `quality`（ok/review）, `bbox`可选。
- `rules`: `id`（Q/F/S/T/R/P+3位数字）, `kind`（qualification/invalid/business/technical/requirement/price）, `title`, `text`, `sources`（[{file_id,block_id,quote,page}]）, `max_score`（可null）, `status`（draft/confirmed/retired）, `revision`（整数）, `subrequirements`字符串列表, `criteria`字典, `conflict`布尔。
- `evidence`: `id`（E+编号）, `file_id`, `title`, `pages`整数列表, `facts`字典, `verification`（candidate/verified/insufficient/rejected）, `notes`, `verified_by`, `file_sha256`。
- `evidence_coverage`: `id`, `task_id`, `block_id`, `block_hash`, `file_id`, `file_sha256`, `actor`, `actor_kind`；每个分块一行，表示该文件在该任务下已完成当前版本覆盖核查，是复用与计分的前提。
- `responses`: `id`, `rule_id`, `evidence_ids`列表, `section_ids`列表, `status`（candidate/supported/insufficient/rejected）, `rationale`, `score`（数字可null）, `missing`字符串列表, `rule_revision`整数, `covered_subrequirements`字符串列表；可增加人员/项目ID及组卷册号等。
- `staff`: `id`, `name`, `available`（true/false/null）, `facts`字典, `source_rows`列表；不凭姓名合并不同ID人员。
- `history`: `id`, `name`, `contract_no`, `contract_date`, `roles`（[{staff_id,name,role}]）, `facts`字典, `source_rows`列表。
- `plans`: `id`（SEC+数字）, `title`, `rule_ids`, `content_points`字符串列表, `fact_refs`列表, `method_refs`列表, `visuals`列表, `volume`默认技术部分, `status`（draft/confirmed）。
- `sections`: `id`与策划一致, `title`, `path`（Markdown相对路径）, `sha256`, `rule_ids`, `volume`, `status`（draft/confirmed/stale）, `writer_id`。
- `reviews`: `id`, `section_id`, `reviewer_id`, `writer_id`, `section_sha256`, `round`, `findings`（[{finding_id,rule_id,severity,message,suggestion,location,state,resolution_refs}]）, `resolutions`（[{finding_id,basis,evidence_ids,location,section_sha256,actor,at}]）, `scores`（[{rule_id,score,reason}]）, `status`；历轮记录保留，只有带当前正文sha与有效证据的resolutions才能关闭旧发现。
- `forms`: `id`, `title`, `template_path`（项目相对路径）, `output_path`, `fields`字典, `required_fields`列表, `volume`默认商务部分, `status`（draft/confirmed）, `source_refs`列表。
- `tasks`: 由主工作流模块管理，其他模块不直接写入。拆标任务被后来的任务接管部分分块后，
  原 `dependencies` 和输入指纹保持不变，并在 `handover_to` 记录 `{接管任务ID: [分块ID]}`。
  尚未完成且分块重叠的拆标任务标记为过期；证据等其他阶段任务不受覆盖归属转移影响。
- `analysis_coverage`: `id`, `block_id`, `block_hash`, `task_id`, `actor`；一个分块只归属一个任务，
  此表记录当前覆盖归属，任务依赖记录当时输入，两者用途不同。
- `confirmations`: `id`, `scope`, `actor`, `actor_kind`（human）, `attestation`（human）, `at`, `fingerprint`；缺少人工声明的旧记录不满足门槛。
- `manual_checks`: `id`, `title`, `status`（pending/confirmed/rejected）, `actor`, `actor_kind`（human）, `attestation`（human）, `notes`, `dependencies`, `fingerprint`, `product_hashes`（成品涉及`{册:docx|pdf: sha256}`）, `bound_at`。
- `ready_history`: `id`, `run_id`, `at`, `outputs`, `hashes`, `positions`, `final_review_id`, `signature_status`, `input_fingerprint`；待签章成品单独锁存，之后的`build --mode review`不覆盖。
- `issues`: `id`, `severity`（error/warning/info）, `category`, `message`, `refs`列表, `status`（open/resolved）。

`02_招标拆解/bid_spec.json` 为派生汇总：`confirmed_facts`、`confirmed_settings` 来自主记录，
`proposed_facts`、`proposed_settings` 为 Agent 提议，尚不能当作人工确认结果。规则确认是否有效仍以
`confirmations` 中的当前版本指纹为准。此汇总不再使用旧的 `facts`、`settings` 字段名。

`sync` 返回 `stale` 和 `source_drift`。后者列出导入来源发生变化或暂时无法读取的文件编号，
并记录提示；不会覆盖项目副本。新版本重新导入、原件恢复一致或记录停用后，自动关闭该检测器的旧提示。
重新导入不自动废止旧规则，仍须通过补遗任务核对版本关系。
- `positions`: `id`, `volume`, `target_id`（SEC或E或表单编号）, `bookmark`, `printed_page`, `pdf_page`, `output_path`。

## 字典集合

- `facts`: 用户确认的共用字段值，例如 `project_name,company_name,deadline,service_period,price`；本地新建只有项目名，其余不得编造。
- `settings`: `anonymous=false,allow_indices=true,volumes=[],max_review_rounds=2,context_budget=16000`。
- `assembly`: 保存本次组卷结果、输入快照及QA状态。

## 分工入口

解析模块 `ingest.py`：`ingest(project,source,category='招标文件',ocr=False)->dict`；`reindex(project)->dict`；`search(project,query,categories=None,limit=20)->dict`；`import_ledger(project,path,mapping=None)->dict`。

匹配模块 `matching.py`：`match(project)->dict`、`score(project)->dict`、`optimize_staff(project,config)->dict`、`audit(project)->dict`、`render_reports(project)->dict`。配置及约束含义由模块文档补充，必须保守处理未证实事实。

组卷模块 `assembly.py`：`build(project,mode='review',split=False,render=True)->dict`、`verify_output(project)->dict`；`forms.py`：`fill_form(project,form_id)->dict`。独立读取以上主记录。返回文件路径、状态、错误/警告；不能把未分页文件标成最终完成。

所有模块新增测试使用 `Project.create(path,name,company_library=None)` 初始化临时项目。公开路径对象可接收 Path 或字符串。错误使用 ValueError 或自定义 RuntimeError，CLI统一输出中文JSON错误。
