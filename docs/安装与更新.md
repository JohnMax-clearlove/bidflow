# 安装与更新

BidFlow 在 Windows 上提供一键安装入口，用 uv 管理隔离的 Python 与依赖。安装不要求管理员权限，不改系统级 ExecutionPolicy，不需要预装 Git 或 Python；npm 渠道需要 Node.js 18+，其余渠道不需要 Node。安装也不会安装 Office、购买许可证、配置模型 API 或启动任何 Agent 任务。

## 支持环境

- Windows 10/11，Windows PowerShell 5.1 或 PowerShell 7 均可。
- 安装、更新、回滚和卸载只使用本机绝对路径与官方 HTTPS 地址。
- 完整的 Word 分页、页码与链接验收仍需 Windows 桌面版 Microsoft Word。其它平台可直接用 uv 安装（见下文）。

## 一键安装

在 PowerShell 中执行：

```powershell
irm https://raw.githubusercontent.com/JohnMax-clearlove/bidflow/main/install.ps1 | iex
```

脚本会：

1. 默认把 `main` 经 GitHub API 解析为完整 commit SHA（传入 40 位 SHA 时跳过解析）；
2. 从该 SHA 的 GitHub/codeload 归档执行 `uv tool install --python 3.12`，必要时由 uv 自动下载 Python 3.12；
3. 运行新入口的 `bidflow doctor`，确认 Python 3.12 与核心模块可用；
4. 通过后才切换稳定入口 `%LOCALAPPDATA%\BidFlow\bin\bidflow.cmd` 与 `state.json`。

如果不想直接执行远程脚本，可以先下载、查看再运行：

```powershell
irm https://raw.githubusercontent.com/JohnMax-clearlove/bidflow/main/install.ps1 -OutFile "$env:TEMP\bidflow-install.ps1"
Get-Content "$env:TEMP\bidflow-install.ps1" | more
$code = Get-Content -Raw -Encoding UTF8 "$env:TEMP\bidflow-install.ps1"
& ([scriptblock]::Create($code))
```

脚本按 UTF-8 无 BOM 保存，以便 `irm | iex` 在 Windows PowerShell 5.1 与 PowerShell 7 中都能正确读取中文；5.1 的 `-File` 参数会按本地代码页误读中文，所以本地执行统一显式按 UTF-8 读取。需要参数时直接在后面追加：

```powershell
$code = Get-Content -Raw -Encoding UTF8 .\install.ps1
& ([scriptblock]::Create($code)) -WithOcr -NoPath
```

## 参数

| 参数 | 说明 |
|---|---|
| `-InstallRoot <路径>` | 安装根目录，默认 `%LOCALAPPDATA%\BidFlow`，必须是本机绝对路径 |
| `-Ref <提交>` | `main`、分支、标签或 40 位 SHA，默认 `main` |
| `-WithOcr` | 安装可选 OCR 依赖（rapidocr、onnxruntime） |
| `-NoOcr` | 明确不安装 OCR，并覆盖上次的 OCR 选择 |
| `-NoPath` | 不修改用户持久 PATH；当前窗口仍临时可用 |
| `-Rollback` | 回滚到上一份 release，不联网、不重新下载 |
| `-Uninstall` | 卸载本安装器管理的内容并移除它加的用户 PATH 条目 |

示例：

```powershell
# 安装指定标签，并带上 OCR
& ([scriptblock]::Create((Get-Content -Raw -Encoding UTF8 .\install.ps1))) -Ref v0.2.0 -WithOcr

# 固定 40 位 SHA（跳过 GitHub API 解析）
& ([scriptblock]::Create((Get-Content -Raw -Encoding UTF8 .\install.ps1))) -Ref 09b0e046ecb669ee5895544512ba2c1da89f13b2

# 只更新、不改持久 PATH
& ([scriptblock]::Create((Get-Content -Raw -Encoding UTF8 .\install.ps1))) -NoPath
```

`-Rollback` 与 `-Uninstall` 互斥，且不能再指定 `-Ref`、`-WithOcr`、`-NoOcr`；错误组合会在任何下载或修改之前被拒绝。

## 其他安装渠道（npm / curl）

以下渠道与一键安装效果相同：都以固定 commit 安装 `bidflow-local`，布局、更新与卸载行为一致。

### npm 渠道（需要 Node.js 18+；计划中，尚未发布）

> **该渠道尚未发布到 npm**：包名 `bidflow` 目前无主，`npm install -g bidflow` 会返回 404。请先使用一键安装或 curl 渠道；发布后再按下方命令使用。

npm 包 `bidflow` 只是安装引导与命令转发，不含业务逻辑；本机未安装时，运行任何命令都会先自动执行上述 PowerShell/bash 安装流程：

```powershell
# 安装引导包并首次安装
npm install -g bidflow
bidflow doctor

# 或不全局安装，直接用 npx
npx bidflow@latest doctor
```

安装管理参数与安装脚本一一对应：`--with-ocr`、`--no-ocr`、`--no-path`、`--rollback`、`--uninstall`、`--ref <提交>`、`--install-root <绝对路径>`；其余参数原样转发给 `bidflow`。环境变量 `BIDFLOW_REF`（默认安装提交）与 `BIDFLOW_INSTALL_ROOT`（安装根目录，默认 `%LOCALAPPDATA%\BidFlow` 或 `~/.bidflow`）也可以控制行为。`bidflow --help` 查看说明。

### curl 渠道

Windows 上用 curl 下载后按“一键安装”的方式运行：

```powershell
curl.exe -fsSL https://raw.githubusercontent.com/JohnMax-clearlove/bidflow/main/install.ps1 -o "$env:TEMP\bidflow-install.ps1"
$code = Get-Content -Raw -Encoding UTF8 "$env:TEMP\bidflow-install.ps1"
& ([scriptblock]::Create($code))
```

Linux/macOS 使用 bash 安装器（需要 curl 与 bash；布局、doctor 检查、回滚与卸载与 Windows 版一致）：

```bash
curl -fsSL https://raw.githubusercontent.com/JohnMax-clearlove/bidflow/main/install.sh | bash
```

参数对应 `--ref`、`--with-ocr`/`--no-ocr`、`--install-root`、`--no-path`、`--rollback`、`--uninstall`。Linux/macOS 默认安装根目录为 `~/.bidflow`；可以生成与检查文档，但完整 Word 分页与链接验收仍需 Windows 桌面版 Word。

## 安装位置与边界

```text
%LOCALAPPDATA%\BidFlow\
├─ bin\bidflow.cmd              稳定入口，用户 PATH 中只添加这一处
├─ releases\<SHA>-core|ocr-*    每次安装一个独立 release
├─ runtime\                     仅当系统没有可用 uv 时安装的专用 uv
├─ cache\                       uv 下载缓存
├─ state.json                   当前/上一份 release、SHA、版本、OCR 选择
└─ .bidflow-install.json        产品标记
```

- 安装目录与投标项目、公司资料彻底分开；默认目录不是本仓库，也不是当前项目目录。
- 只接受空目录或带 BidFlow 产品标记的目录；非空且无标记的目录会被拒绝，不静默占用。
- 系统目录、盘根、用户主目录本身、UNC 路径以及含 `% ; " & | < > ^` 等命令解释字符的路径会被拒绝。
- 所有写入与递归删除都限制在安装根目录内，并逐级检查目录联接/符号链接；发现重解析点会拒绝越界操作。

## 更新、回滚与卸载

```powershell
# 更新到 main 最新提交（重复执行一键命令即可）
irm https://raw.githubusercontent.com/JohnMax-clearlove/bidflow/main/install.ps1 | iex

# 回滚到上一份 release：先对旧入口运行 doctor，通过后原子切换
$code = Get-Content -Raw -Encoding UTF8 .\install.ps1
& ([scriptblock]::Create($code)) -Rollback

# 卸载
& ([scriptblock]::Create($code)) -Uninstall
```

- 升级失败（下载、安装或 doctor 不通过）时，稳定入口与 `state.json` 保持原样，失败的 release 目录会被清理。
- 回滚和卸载不联网、不安装 uv，只处理带产品标记且校验通过的内容。
- 卸载只删除本安装器管理的入口、release、runtime、cache、状态文件以及它自己添加的用户 PATH 条目；项目、公司资料、未知文件和共享 uv/Python 一律保留，并在输出中明确报告保留内容。

## 第一次使用

安装成功后请**新开一个终端**，或重新打开 Agent，以继承新的 PATH：

```powershell
bidflow doctor
bidflow init "项目名" --path "D:\投标项目\项目名"
```

之后在 Agent 中打开新创建的项目文件夹即可开始工作。更新后同样建议重开终端。

## OCR 与依赖说明

- `-WithOcr` 会安装 rapidocr 与 onnxruntime；`-NoOcr` 覆盖上次选择并不装 OCR。未指定时沿用上次选择，全新安装默认不装。
- BidFlow 不联网下载 OCR 模型；已装依赖但模型未就绪时，doctor 会明确提示，扫描件生成待核提示而不是假称可用。
- 缺少桌面版 Word 或 Pandoc 只给出明确警告，不阻止核心安装；缺少 Python 3.12 或核心依赖则视为安装失败。

## PATH 行为

- 默认把 `<安装根>\bin` 加入**用户** PATH；不加系统 PATH，不要求管理员。
- `-NoPath` 不修改任何持久 PATH，只保证当前进程窗口可用；需要长期使用时请自行把 `<安装根>\bin` 加入 PATH。
- 卸载只移除由本安装器添加的条目；如果该路径原本已存在，卸载不会删除它。

## 跨平台或不用本脚本

任何平台都可以直接用 uv 从固定 SHA 安装（需要自行安装 uv）：

```bash
uv tool install --python 3.12 "bidflow-local @ https://codeload.github.com/JohnMax-clearlove/bidflow/tar.gz/<完整40位SHA>"
uv tool install --python 3.12 "bidflow-local[ocr] @ https://codeload.github.com/JohnMax-clearlove/bidflow/tar.gz/<完整40位SHA>"
```

Linux/macOS 可以生成与检查文档，但完整 Word 分页与链接验收仍需 Windows 桌面版 Word。

## 开发者从源码安装

在仓库总文件夹使用 Python 3.12：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\bidflow.exe doctor
```

OCR 可选依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[ocr]"
```

## 安全说明

- 只从 `astral.sh` 官方 HTTPS 地址下载固定版本 uv 安装器，不关闭 TLS 校验，不使用随机镜像，不静默修改代理。
- 已有 uv 时直接复用，不升级、不卸载用户共享的 uv；系统已有的 Python 也不会被删除。
- 安装器设置的 `UV_*` 环境变量只作用于本次进程，并在结束时恢复；不改 `HOME`、`USERPROFILE` 等用户变量。
- 不自动配置模型 API、不安装 Office、不启动任务、不改用户项目内容。

## 故障排查

- **无法解析 Ref**：多为网络或 GitHub 访问受限，可改用完整 40 位 SHA。
- **doctor 不通过**：错误会列出缺少的核心模块；确认磁盘空间与网络后可重试，旧版本仍然可用。
- **命令找不到**：新开终端；或执行 `-NoPath` 后改用完整路径 `<安装根>\bin\bidflow.cmd`。
- **重解析点被拒绝**：安装根下存在目录联接/符号链接；请清理后重试，安装器不会跟随链接写入或删除。
- **卸载保留了文件**：输出会列出保留路径；确认无用后手动清理，再次安装前请改用空目录。
